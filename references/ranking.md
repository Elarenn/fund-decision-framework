# 同类排行榜怎么算（Ranking Methodology）

> 目标：让"排名"可比、可复核。不产出"买哪只"，只产出"在哪个池子里、按什么口径、第几名、百分位多少"。

## 一、三条铁律

1. **同池才可比**。排名必须绑定「数据源 + 分类池 + 池大小 + 截至日期」四要素。缺任一项，排名无效。
2. **跨平台只比数值，不比名次**。不同销售平台 / 数据商的分类池不同（A/C 份额是否合并、是否混入利率债或二级债），分母不同，名次不可直接对比。
3. **排名是过去式**。高排名来自既定持仓与久期，不能线性外推到未来三个月。

## 二、可比性的四个前提（算之前先确认）

| 前提 | 为什么 | 检查方法 |
|---|---|---|
| 同一数据源 | 不同平台分类池不同 | 全程只用同一个工具取数 |
| 同一分类池 | "短期纯债"与"债券型-短债"是两个池 | 记录池大小 N（分母） |
| 同一份额类型 | A/C/E 份额费率与净值不同 | 分开排名，不混 |
| 同一时间窗 | 近1月/近3月口径必须一致 | 统一起止日 |

## 三、指标口径（怎么选）

- **固收/短债类**：以**近1月、近3月**为主口径。原因：久期短，近1年数据被旧行情稀释；近1月/近3月最能反映当下。
- **权益类**：近1月、近3月、近1年、今年来同时看，并配最大回撤。
- **必须成对出现**：任何收益数字都要配**最大回撤**或**波动**，单看收益排名会系统性偏向久期长/信用下沉的产品。

## 四、必填字段清单（展示一只基金时至少给全这些）

展示 = 客观数据罗列 ≠ 推荐。任何出现在对照表里的标的都要给：

1. 基金代码
2. 基金全称
3. 投向 / 跟踪指数
4. 规模
5. 近1年 / 今年来收益
6. 近1月 / 近3月收益（短债核心）
7. 最大回撤
8. 申购费 / 赎回费分档 / 是否有锁定期

> 缺字段时明确标注"未核到"，禁止估算填充。

## 五、排名的计算步骤

1. 取数：同一数据源、同一分类池、同一时间窗，记录池大小 N。
2. 计算每只的指标值（近1月、近3月、近1年、最大回撤）。
3. 按单一指标降序排名，得到 rank（1 = 最高）。
4. 计算百分位：`percentile = rank / N`（越小越好）；表述为"前 X%"。
5. 收益排名与回撤排名**并列展示**，禁止只展示收益排名。

用 `scripts/calc.py rank` 完成第 3–5 步：

```bash
python scripts/calc.py rank --data funds.json --metric m3 --pool-size 1000
```

`funds.json` 格式见脚本内 `--help`。

## 六、常见坑（必须主动提示使用者）

- **近1月/近3月高 ≠ 更好**：主要来自久期长。利率反弹时长久期先回撤。
- **排行榜前排可能是"伪债基"**：含股票/转债的混合二级债在股市涨时冲高，跌时反噬——要在"费率核验"模块用投向字段穿透。
- **迷你基金**：规模过小有清盘风险，排名再好也要标注。
- **A/C 份额混排**：C 类有销售服务费，短期更适合；A 类申购费高但长期更省，不能混排名。
- **限购 / 暂停申购**：排名靠前但买不进，等于无效候选——必须标注申购状态。

## 七、输出样例（方法论表述，非推荐）

```
【口径】<数据源> / <分类池名称> / 池 N 只 / 截至 YYYY-MM-DD
【近3月数值】标的A: X.XX%（前 a.a%）| 标的B: Y.YY%（前 b.b%）| 标的C: Z.ZZ%（前 c.c%）
【对照】使用者当前持有标的近3月 W.WW%（前 d.d%）
【辨析】标的高数值可能来自久期较长，波动更大；利率反弹时回撤会先放大
【边界】以上为方法论与数据整理，不构成投资建议；最终决策与风险由使用者自行承担，数据以自行核实为准。
```
